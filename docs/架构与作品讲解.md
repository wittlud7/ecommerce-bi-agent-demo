# 架构与作品讲解

## 分析链路

模拟数据生成器 → SQLite 事实表与维度汇总 → 本地只读分析工具 → 看板或 Agent → 数据证据与行动建议。

前端保留多维筛选、销量趋势、渠道拆分、销售流向、负责人矩阵、地域下钻、时段、价格带、售后和数据核对页面。业务对象包括日期、商品系列、店铺、渠道、账号、负责人及产品分层。

## Agent 链路

用户问题 → 当前问题范围检查与无关问题拒答 → 页面筛选 → 明确模拟数据期间和维度范围 → 汇总查询 → 等长周期比较 → 变化拆解或趋势查询 → 结构化输出。

默认演示用确定性规则规划工具顺序；可选 LLM 模式由模型选择分析工具并多轮查询。两种 Python 模式都使用同一个 `AnalyticsEngine`，不会连接旧 ERP、公司数据库或原销售接口。

查询范围先在临时模拟库中限定，再交给工具读取。当前期间与对比期间由同一数据日期轴解析；页面最近 7 天的趋势表同时加载前 7 天数据，避免将缺少历史误判成新品起量。

## 面试可讲的产品判断

- 为什么先统一商品、套装、来源和指标，再做图表与问数。
- 为什么管理者需要从总览下钻到具体渠道、账号、负责人和产品。
- 为什么不能把维度贡献直接称为因果归因。
- 为什么回答需要区分事实、计算判断和待验证假设。
- 为什么查询建议与执行业务动作应有明确边界。

## 演示边界

虚构数据用于验证产品框架、交互和工具工作流。该版本没有原系统用户数、公司销量、收入、渠道占比、成本、真实使用日志和模型效果数据。没有用模拟结果证明原项目经营价值。

## 静态发布链路

SQLite 独立模拟库 → 允许列表导出 JSON 与前端 → 浏览器内聚合及离线分析 → GitHub Pages。静态模式不使用 Python 引擎，也不运行任意 SQL；通过回归测试与 SQLite 的期间、筛选、地域、时段、价格带、售后及明细结果对照。

## 两分钟演示

1. 总览切换最近 7 天与 30 天，解释销量与成交额口径。
2. 查看渠道、负责人矩阵和地域下钻，说明如何缩小销售核查范围。
3. 输入“最近7天哪个书系下滑最多？”，展开工具过程，展示前期、本期与变化。
4. 筛选小学后询问“最近7天成交额排行”，证明回答受页面范围约束。
5. 说明维度贡献不等于因果，活动、库存和流量证据需要后续接入。

可继续迭代：以匿名人工标注问题集评估问数正确率、工具选择与引用覆盖；增加自然语言日期与实体歧义处理；在独立服务端配置模型与配额后演示真实 LLM。尚未完成的内容不作为已交付能力描述。
